# pi-ai：统一 LLM 层

<Diagram src="/diagrams/layers.html" title="pi 的四层架构" />

## 要解决的问题

<Say id="b01" cue="ai">先看最底下的 pi-ai，它要解决的问题很具体。</Say>
<Say id="b02" cue="llm">每家模型的接口都不一样：消息格式、工具调用的写法、流式事件，全都不同。</Say>
<Say id="b03" cue="agent">上层的循环不想关心这些，它只想面对一种消息格式。</Say>

## 统一的消息

<Say id="b04" cue="ai">所以 pi-ai 定义了统一的消息，分四种：system、user、assistant，还有工具结果。</Say>
<Say id="b05">消息里的内容块有四类：文本、思考、图片和工具调用。</Say>

```ts
// packages/ai/src/types.ts（简化）
type Message = SystemMessage | UserMessage | AssistantMessage | ToolResultMessage;
type Content = TextContent | ThinkingContent | ImageContent | ToolCall;
```

## provider 和协议分开

<Say id="b06">接下来是一个关键设计：把 provider 和传输协议分开。</Say>
<Say id="b07">provider 负责鉴权和模型列表，目前有四十多个。</Say>
<Say id="b08">它们共用十几种传输协议。比如 groq、deepseek，走的都是 OpenAI 兼容的协议。</Say>
<Say id="b09">协议的实现是按需加载的，用到哪一家，才加载哪一家的代码。</Say>

## 一个入口

<Say id="b10" cue="ai">对上层来说，入口只有一个：streamSimple。给它模型和消息，拿回一个事件流。</Say>
<Say id="b11" cue="agent">事件流里依次是文本增量、工具调用和结束原因，最后还能拿到完整的回复消息。</Say>

```ts
const stream = models.streamSimple(model, { messages });
for await (const event of stream) {
  // text_delta / toolcall_end / done ...
}
const message = await stream.result();
```
